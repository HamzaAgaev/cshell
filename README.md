# cshell

Мой небольшой интерактивный Unix-подобный shell на C (C23) с собственным слоем кэширования блочного I/O. Кэш `cio` живет в пользовательском пространстве, работает по политике LRU и обходит страничный кэш ОС; на нем же я собрал нагрузочные бенчмарки.

## Слой кэша (`cache-library`)

POSIX-подобный API поверх моего кэша: `cioOpen/Close/Read/Write/Lseek/Fsync`. Что внутри:

- **Обход кэша ОС** — `O_DIRECT` на Linux, `F_NOCACHE` на macOS, `posix_fadvise` в остальных случаях.
- **64 блока по 1 МиБ** — каждое обращение выравниваю по границе блока.
- **Политика LRU** — двусвязный список по давности использования и хеш-таблица для быстрого поиска, при переполнении вытесняю хвост.
- **Общие блоки на файл** — файлы различаю по inode и device, поэтому разные дескрипторы одного файла делят одни и те же блоки.
- **Отложенная запись** — измененные блоки записываю на диск при `cioFsync` и при закрытии.
- **Потокобезопасность** — доступ к кэшу закрыт мьютексом.

## Структура

```
shell/              — интерактивный shell (разбор и запуск команд)
cache-library/      — LRU-кэш (`cio.*` — API, `cache.*` — устройство блоков)
test-cache-module/  — тесты кэша (много дескрипторов, многопоточная запись)
benchmark-starter/  — нагрузочные бенчмарки поверх кэша
common/             — общие утилиты
```

## Сборка и запуск

Нужны CMake >= 3.26 и Clang (C23); на Linux и macOS собираю с санитайзерами.

```bash
mkdir build && cmake -Bbuild -H. && cmake --build build

./build/test-cache-module/test-cache-module

python3 inputGenerator.py ./build/benchmark-starter/input.txt
cd build/benchmark-starter && ./benchmark-starter threads 3 3 && cd ../..
python3 benchmarkChecker.py "./build/benchmark-starter"
```

## Форматирование, стиль и CI

Настроены `.clang-format` и `.clang-tidy` для стиля кода, dev-контейнер для окружения и CI, который на каждый push собирает проект и прогоняет бенчмарки с тестами кэша.
